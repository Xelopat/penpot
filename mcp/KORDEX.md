# Компактный аудит прототипа

Проверенная сборка MCP: `2.18.5-kordex.1-9bd1ff8103a5`.
Проверки типов, сборка и 43 теста прошли успешно:
<https://github.com/Xelopat/penpot/actions/runs/41315579562>.
Проверено скачивание без авторизации для Linux amd64 и arm64.
Дайджест: `sha256:6e0d8208f506edc205617eb9e0ace108834ba28fc5a0e6c880526e2b71768659`.

`audit_prototype` читает структуру страницы и возвращает короткую сводку:
количество объектов, экранов, сценариев и действий, число ошибок и
предупреждений, а также ограниченный список проблемных объектов с ID.

Проверяются отсутствующие назначения, переходы на исключённые из просмотра
экраны, стартовые экраны сценариев и ссылки позиционирования окон. Отдельное
предупреждение показывает ссылку на опору другого экрана — частую проблему
при клонировании. Исправлений макета аудитор не выполняет.

По умолчанию возвращаются до 20 замечаний, сначала ошибки. Общие счётчики
охватывают всю выбранную страницу, даже если детали обрезаны. Имена объектов
ограничены 96 символами. Полное дерево страницы и тексты комментариев в ответ
не включаются.

Параметры:

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `pageId` | Текущая страница | Выбрать другую страницу этого файла без переключения редактора |
| `maxIssues` | `20` | От 0 до 100; 0 возвращает только счётчики |
| `expectFixedOverlays` | `false` | Предупреждать об отсутствующей или нефиксированной опоре окна |
| `sameWidthNavigation` | `false` | Предупреждать об изменении ширины между экранами |

Возврат из окна на обычный экран не считается сменой ширины устройства,
если окно используется только как наложение. Другие изменения ширины могут
быть намеренными, поэтому это предупреждение, а не автоматическая ошибка.

Проверка описывает данные Plugin API. Она не нажимает кнопки, не проигрывает
анимации и не подтверждает визуальное центрирование при прокрутке. Поле
`viewerBehaviorVerified` всегда равно `false`. Отсутствующая `apiVersion`
также не доказывает разрыв соединения: старые метки сборки могут возвращать
`null` при работающем редакторе.

## Совместимость с существующим подключением

Даже если клиент ещё не обновил список инструментов, в прежнем
`execute_code` доступна та же функция:

```javascript
return penpotUtils.auditPrototype({ maxIssues: 20 });
```

Сервер устанавливает её в контекст перед выполнением кода. Остальные
переменные, результат пользовательского кода и `storage` сохраняются.
Это расширение требует только обновления сервера MCP. Браузерный плагин и
контейнер интерфейса не нужно пересобирать ради аудитора.

## Установка на сервер

В существующем Compose-файле замените **только image сервиса `penpot-mcp`**:

```yaml
penpot-mcp:
  image: "ghcr.io/xelopat/penpot-mcp:2.18.5-kordex.1"
```

Все существующие настройки сервиса, сети и зависимости сохраните.
Из папки действующей установки выполните команды с прежними параметрами
Compose-проекта и `.env`, если они использовались:

```bash
docker compose pull penpot-mcp
docker compose up -d --no-deps penpot-mcp
```

При перезапуске соединение MCP кратковременно прервётся. Редактор Penpot
может переподключиться сам; при необходимости обновите его вкладку.
Для появления отдельного `audit_prototype` обновите подключение Penpot в
клиенте. Прежний `execute_code` поддерживает приведённый выше вызов независимо
от кеша списка инструментов клиента.

Образ основан на официальном `penpotapp/mcp:2.18.5` и использует его
настройки запуска и зависимости. Предыдущие исправления самого интерфейса
Penpot поставляются отдельно: [инструкция frontend](../docker/kordex/README.md).

## Разработка

Из `mcp/`:

```bash
pnpm install --frozen-lockfile
pnpm --filter mcp-common build
pnpm --filter mcp-server types:check
pnpm --filter mcp-server test
pnpm --filter mcp-server build
```

Браузерная часть аудитора собирается esbuild в самостоятельный скрипт;
`src/generated/PrototypeAuditBundle.ts` генерируется перед сборкой и тестами.
Тесты исполняют именно этот скрипт, проверяя сериализацию, ограничения
ответа, сохранение контекста и отсутствие изменений в моделях макета.
